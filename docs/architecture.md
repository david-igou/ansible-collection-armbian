# Architecture

## Overview

```
┌─────────────────────────────────────────────────────────┐
│                    RouterOS Switch/Router                │
│  DHCP server — static leases per board MAC              │
│  Normal state:  no PXE options                          │
│  Netboot state: option 66 (TFTP server) added           │
│                 option 67 (boot file) added              │
└──────────────┬──────────────────────────┬───────────────┘
               │                          │
    ┌──────────▼──────────┐    ┌──────────▼──────────────┐
    │   Netboot Server    │    │       Board (RK3588)     │
    │                     │    │                          │
    │  ┌───────────────┐  │    │  U-Boot (SPI or eMMC)   │
    │  │ netboot.xyz   │  │    │                          │
    │  │ (Docker)      │◄─┼────┤  1. DHCP → get next-    │
    │  │               │  │    │     server + boot opts   │

    │  │ HTTP :8080    │  │    │  3. TFTP kernel/initrd/ │
    │  └───────────────┘  │    │     DTB                  │
    │                     │    │  4. Boot into NFS root   │
    │  ┌───────────────┐  │    └──────────────────────────┘
    │  │ NFS Server    │  │
    │  │               │  │

    │  ┌───────────────┐  │

    │  │ (Armbian img) │  │
    │  └───────────────┘  │
    └─────────────────────┘
```

## Boot Modes

### Normal (disk boot)
RouterOS DHCP has no PXE options for the board. U-Boot falls through
its `distro_bootcmd` and boots from NVMe or eMMC as usual.

### NFS Root (diskless)
1. Ansible runs `enable_netboot.yml` with `netboot_mode=nfsroot`
2. RouterOS DHCP option set is assigned to the board's static lease
3. Board is rebooted
4. U-Boot gets next-server + boot-file from DHCP
5. U-Boot downloads `pxelinux.cfg/01-<mac>` from TFTP
6. U-Boot downloads kernel, initrd, DTB
7. Board boots into Armbian rootfs mounted from NFS (read-only, /exports/rootfs/<model>)

### Reprovision
Same as NFS root, but the NFS export is `/exports/reprovision/<model>` (read-write)
and the kernel cmdline includes `reprovision=1`. On boot, systemd starts
`reprovision.service`, which:

1. Reads `/etc/reprovision.conf` (credentials on NFS server, not board disk)
2. Downloads `<model>.img.xz` from the nginx image server
3. Flashes it to NVMe or eMMC (`xz -dc | dd`)
4. Calls RouterOS REST API to clear the PXE DHCP option for this board's MAC
5. Reboots — board comes up from freshly flashed disk

## Bootloader Strategy

### SPI available (Orange Pi 5, Orange Pi 5 Pro, Orange Pi 5 Max, Rock 5B)
Armbian U-Boot is flashed to SPI flash (`/dev/mtd0`). U-Boot's `distro_bootcmd`
includes PXE as a boot target. When RouterOS assigns PXE options, U-Boot picks
them up immediately on the next power cycle — no board-side configuration change
needed.

### No SPI (Rock 5A, boards with unpopulated SPI socket)
Armbian U-Boot is flashed to the eMMC boot partition (`/dev/mmcblk0boot0`).
To prioritise PXE over the local disk, Ansible SSHes to the board before
triggering reprovision and runs:
```
fw_setenv boot_targets "pxe dhcp mmc0 nvme0 mmc1"
```
The reprovision script restores the normal order after flashing:
```
fw_setenv boot_targets "mmc0 nvme0 mmc1 pxe dhcp"
```

> **Limitation**: if the board's disk OS is broken and no SPI is present,
> automatic PXE boot is not possible without a bootable SD card fallback.

## TFTP File Layout

Served from `/opt/netbootxyz/config/` on the netboot server:

```
pxelinux.cfg/
  01-aa-bb-cc-dd-ee-ff    # per-board, generated by Ansible (enable_netboot)
  nfsroot-default         # shared fallback for NFS root mode
  reprovision-default     # shared fallback for reprovision mode

armbian/
  orange-pi-5/
    vmlinuz               # extracted from Armbian image
    initrd.img
    board.dtb
  rock-5b/
    vmlinuz
    initrd.img
    board.dtb
  ...
```

## NFS Export Layout

```
/exports/
  rootfs/
    orange-pi-5/          # read-only Armbian rootfs for NFS boot
    rock-5b/
    ...
  reprovision/
    orange-pi-5/          # read-write, includes reprovision.sh + systemd unit
    rock-5b/
    ...
```

## RouterOS DHCP Objects

Created once by `setup_server.yml` → `routeros_dhcp/setup_options.yml`:

| Object type    | Name                          | Purpose                       |
|----------------|-------------------------------|-------------------------------|
| dhcp-option    | armbian-tftp-server           | option 66 = netboot server IP |
| dhcp-option    | armbian-nfsroot-bootfile      | option 67 = pxelinux.cfg path |
| dhcp-option    | armbian-reprovision-bootfile  | option 67 = pxelinux.cfg path |
| option set     | armbian-nfsroot               | bundles option 66 + nfsroot 67|
| option set     | armbian-reprovision           | bundles option 66 + reprov 67 |

Per board, only the static lease's `dhcp-option` field is changed:
- Netboot: `dhcp-option=armbian-nfsroot` or `dhcp-option=armbian-reprovision`
- Normal:  `dhcp-option=""` (empty)

## Ansible Collections Required

Install with `ansible-galaxy collection install -r ansible/requirements.yml`:

- `community.routeros` ≥ 2.0 — RouterOS API/command modules
- `community.docker` ≥ 3.0 — docker_compose_v2 module
- `ansible.netcommon` ≥ 5.0 — network_cli connection plugin
